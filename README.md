I build useful software where **security, AI, developer tooling, infrastructure, and distributed systems** overlap. Most of my projects start with a question: *can this be made simpler, safer, or easier to understand?*

I like small tools, strong system models, experiments that can be tested, and sharing what survives contact with reality.

**Start here:** [OpenReflex](https://openreflex.cc) · [agent-plane](https://agent-plane.cc) · [writing](https://medium.com/@vishnucyber)

## Featured builds

### [OpenReflex](https://openreflex.cc) — muscle memory for coding agents

A local-first layer for Claude Code, Codex, Cursor, and OpenCode that remembers useful execution experience, retrieves what worked before, and notices loops or stalled approaches while you work.

`Developer Tools` `Python` `Agent Memory` `MCP` `Local-first`

[Website](https://openreflex.cc) · [Source](https://github.com/vishnu-77/openreflex) · [Docs](https://openreflex.cc/docs) · [PyPI](https://pypi.org/project/openreflex/)

### [agent-plane](https://agent-plane.cc) — runtime boundaries for autonomous software

A control plane for seeing what software agents are doing and putting explicit boundaries around consequential actions. It explores identity, authority, delegation, approval, enforcement, and evidence without pretending every integration can block everything.

`Security` `Runtime Systems` `Identity` `Policy` `MCP`

[Website](https://agent-plane.cc) · [Source](https://github.com/vishnu-77/agent-plane) · [Quickstart](https://github.com/vishnu-77/agent-plane/blob/main/docs/quickstart.md)

## Current rabbit holes

- What should software remember — and what should it deliberately forget?
- When should an automated system decide **not** to reply, call a tool, or take an action?
- Can execution histories become reusable knowledge rather than dead logs?
- How do distributed systems preserve intent as work crosses identities, services, and trust boundaries?
- How do we make security controls developers actually want to keep enabled?
